# Tone

从零创建的原生 iPhone 音高工具 MVP，使用 SwiftUI 和 AVAudioEngine。最低系统版本 iOS 17，无第三方运行依赖。第一版采用中文、深色界面，标准为十二平均律、A4 = 440 Hz。

## 已实现的代码

- **音高 · 调音**：麦克风输入 → 单音基频识别 → 最近音名（含八度）→ 实际频率 → 带正负号的音分偏差 → 指针。左侧偏低，右侧偏高。打开调音页自动收音；提供记住选择的人声／乐器档、稳定音名、阻尼指针、最近三秒音高轨迹、输入电平、短暂保留读数及权限错误处理。人声绿色区域为 ±15 音分，乐器为 ±5 音分。
- **主音线索**：选择「只看音高」「主音」或「属音」。选择主音时显示当前音名；选择属音时向下纯五度换算主音，例如 G → C、C → F。这依赖用户对音级的判断，不自动判断大小调。
- **标准音**：中央 C4（261.63 Hz）、A4（440 Hz）快捷按钮，以及一个完整半音音阶的按钮 pad。按住发声、松开停止，支持 C2–C3 到 C6–C7 的八度切换。纯正弦波有约 5 ms 渐入渐出，播放标准音时停止麦克风检测。
- 标准音页暂停收音，返回调音页自动恢复；后台停止音频，前台恢复当前页面所需音频。系统中断结束且允许恢复时自动继续，否则提供重试；耳机变化及音频服务重置后重建引擎。VoiceOver 可双击标准音按钮切换播放，再次双击停止。
- 音频在设备上处理；没有录音文件、网络请求、账号或数据上传。

已使用 Xcode 27.0 完成模拟器和 iPhone 设备版本的编译，并在 iOS 27.0 的 iPhone 18 Pro 模拟器中启动。真机行为和实际调音精度尚待验证。

## 启动 iPhone App

1. 在 Mac 上准备完整 **Xcode 16 或更新版本**及 iOS 平台支持。仅 Command Line Tools 无法构建此 App。
2. 打开 `Tone.xcodeproj`，选择 **Tone** scheme。
3. 在 **Signing & Capabilities** 中选择自己的 Team，并把 `com.example.Tone` 改成自己的唯一 Bundle Identifier。此处是开发占位标识。
4. 选择 iPhone 或 iOS Simulator，运行。界面可先在模拟器检查；输入音高和扬声器行为优先在真机测试。
5. 打开「音高 · 调音」，首次使用允许麦克风权限，之后自动收音。持续唱或弹一个单音即可检测。拒绝权限后可通过界面打开系统设置；「标准音」不需要麦克风权限。

命令行编译（脚本会优先使用 `/Applications/Xcode.app`，无需改变系统的全局开发工具选择）：

```sh
sh scripts/build-ios.sh
```

### 0.1.1 真机反馈修复（2026-10-11）

用户已实际使用首版：标准音可以发声，但触摸后有明显延迟；Stylophone 仅 B4 以上较稳定，A4 及更低音和人声没有读数。此前合成音测试未覆盖弱输入和忙碌时的采集连续性，因此不能证明首版真机检测可靠。

修复：

- 标准音改用 UIKit 触摸按下事件，关闭该页滚动容器的触摸等待；抬手、移出按钮和系统取消均结束发声。
- 进入标准音页就预热音频引擎，松手后引擎静音运行，换页、进入后台或系统中断才关闭。请求 5 ms I/O 缓冲，实际硬件延迟仍须真机确认。
- 每个麦克风音频块都进入连续滑动窗口；分析线程繁忙时仅跳过分析，不再拼接丢失音频块前后的样本。
- YIN 差分计算改用 Accelerate/vDSP，降低 Debug 构建的计算负担。RMS 门槛从 0.008 降至 0.0005；严格周期匹配失败时允许更宽的周期置信门槛，仍拒绝非周期噪声。
- 输入电平采用对数显示；没有音高时提示声音太轻，或已收到声音但尚未找到稳定单音。

新增测试覆盖 82–494 Hz 较弱的丰富泛音信号，以及 110/220/440 Hz 轻微颤音经过真实窗口、降采样代码并跳过部分分析窗口的情况；共 229 项检查通过，7 项 XCTest 也通过。**0.1.1（build 2）已成功签名构建、更新安装，并由设备工具确认在 iPhone 16 Pro 上启动。** 用户尚未反馈本次低音、人声识别和按下延迟的复测结果；合成颤音不是录制的真人声音。

### 0.1.2 自动收音与稳定显示（2026-10-11）

- 默认人声档，使用 AppStorage 保存模式；人声／乐器分别采用 5／3 次中值、250／80 ms 平滑时间常数、3／2 次新音确认和 10／5 音分的分界缓冲。
- 初次建音置信门槛 0.80，跟踪门槛 0.75，保留 RMS 0.0005 的弱输入门槛。孤立跳音先等待确认，不能直接推动指针；确认换音后清空旧音平滑和轨迹。
- `PitchTracker` 接收检测值、音量和单调时钟，输出锁定音名、平滑频率、相对该音的偏差和可信状态。指针额外线性过渡 80 ms；轨迹保留可信原始偏差，缺失区间不连线，范围 ±75 音分，超过范围裁切。
- 没有可信结果时指针变灰；300 ms 后隐藏指针，最后音名标注「上次检测」，1 秒后清空。50 ms 时钟检查保证音频回调停止时也能清除旧读数。
- 自动收音由页面、前台状态及系统中断状态共同决定；异步授权完成后重新核实当前页面，避免在标准音页或后台误启动麦克风。权限和重试提示在页面顶部。
- 21 项 XCTest、229 项独立检查通过。新增测试覆盖边界、颤音、持续偏移、八度误判／真实换八度、起音错误、滑音、静音、置信门槛、断流、顺序错误和生命周期状态；82–494 Hz 的弱泛音颤音叠加噪声经过实际窗口和降采样管线，合成首次稳定结果均小于 0.5 秒。这不是实际 iPhone 延迟或真人准确度证明。

## 检测范围与调性

当前检测范围约 **55–1600 Hz（A1 至 G6 附近）**，适合单人唱出持续音或乐器逐个弹奏。标准音 pad 的播放范围更广，超出检测范围的音仍可试听。多音和弦、整首歌混合音频、强噪声及缺少基频的复杂音色不保证识别；当前不做自动歌曲调性推断。

如果用户已确认唱的是主音，检测到的音名可作为调性线索；若确认是属音，界面可按音级关系推回主音。但听到一个音不能单独判断歌曲调性或大小调。标准音和音名以十二平均律为准，不提供乐器音色模拟或转调乐器显示。

## 代码结构

| 路径 | 用途 |
| --- | --- |
| `Tone/UI/ContentView.swift` | 调音页、指针、标准音 pad、权限提示 |
| `Tone/Audio/AudioController.swift` | 麦克风、后台分析、音高平滑、正弦波、音频生命周期 |
| `Tone/Core/PitchDetector.swift` | YIN 周期检测与亚采样插值 |
| `Tone/Core/PitchTracker.swift` | 独立音高跟踪、历史、超时状态和音频活动意图 |
| `Tone/Core/PitchInputWindow.swift` | 连续音频窗口与降采样；分析跳帧时保留采集连续性 |
| `Tone/Core/MusicalNote.swift` | MIDI 音名、频率、音分计算及主音／属音换算 |
| `Tone/Core/SineOscillator.swift` | 与音频回调共用的标准音波形及渐入渐出 |
| `Tests/CoreChecks/main.swift` | 无需 XCTest 的核心检查 |
| `Tests/ToneCoreTests/` | 完整开发环境使用的 XCTest |
| `scripts/generate_project.py` | 无第三方依赖的 Xcode 工程生成器 |
| `scripts/build-ios.sh` | 使用完整 Xcode 构建模拟器版本 |

新增 Swift 文件后运行 `python3 scripts/generate_project.py`。生成器会重写工程和 scheme；手动调整签名或其他工程设置后，应先把相应设置同步到生成器，避免再次生成时丢失。
